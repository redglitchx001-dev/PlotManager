#                         OVERVIEW                                    #

PlotManager V1 is the most advanced, feature-packed survival plot
management plugin ever created for Minecraft. It allows players to
claim land anywhere in a normal survival world using a Golden Axe
wand, protect it, upgrade it, and watch it grow into an empire.

It features 44+ premium systems including a built-in Discord JDA bot,
BlueMap 3D web sync, FAWE terrain rollback, a full economy with
generators and vaults, ITS OWN BUILT-IN HOLOGRAM SYSTEM (no external
hologram plugins needed!), and the most powerful admin toolkit ever made.

Target: Paper 1.21.x (1.21, 1.21.1, 1.21.2, 1.21.3, 1.21.4, 1.21.5, 1.21.6, 1.21.7, 1.21.8, 1.21.9, 1.21.10, 1.21.11, 26.0, 26.1, 26.2)

IMPORTANT DESIGN RULES:
  - The plugin has ITS OWN built-in hologram rendering system using
    ArmorStand entities with custom names. It does NOT depend on any
    external hologram plugin (no FancyHolograms, no HolographicDisplays).
  - The plugin uses ProtocolLib ONLY if available for enhanced packet
    features, but works 100% WITHOUT it using ArmorStand fallback.
  - ALL text, colors, prefixes, messages, GUI titles, hologram lines,
    sounds, items, lore lines, and formats are configurable in config.yml.
  - NOTHING is hardcoded. If it appears on screen, it's in the config.

# ------------------------------------------------------------------ #
# SECTION 1: THE FOUNDATION & WORLD MECHANICS                       #
# ------------------------------------------------------------------ #

FEATURE 1: 100% ENGLISH & GREEN THEME
  - Every single message, GUI title, command description, config
    comment, and hologram text is in English.
  - Color codes: §2 (dark green) for headers, §a (light green) for
    body text. Prefix: §2§l[PlotManager] §a

FEATURE 2: VAULT ECONOMY INTEGRATION
  - Everything costs in-game money via Vault.
  - Claiming, upgrading, buying generators, unlocking vaults,
    purchasing music — all tied to economy.

FEATURE 3: PAPER 1.21.X COMPATIBILITY
  - api-version set to '1.21' which covers all 1.21.x versions.
  - Compatible with Paper, Spigot, and forks.

FEATURE 4: NO EXPLOSIONS (ABSOLUTE)
  - TNT, Creepers, Withers, Beds, Respawn Anchors, End Crystals —
    ALL of them do exactly 0 block damage ANYWHERE in the protected
    world. This prevents chest/barrel item loss completely.
  - Listeners: EntityExplodeEvent, BlockExplodeEvent — cancelled.

FEATURE 5: ABSOLUTE WILDERNESS PROTECTION
  - Outside of plots (wilderness), players CANNOT break or place
    blocks. They CAN interact (open chests, doors, buttons, levers).
  - This makes claiming mandatory for building.

FEATURE 6: GOLDEN AXE CLAIMING WAND
  - Command: /plot wand (OP only by default)
  - Gives a Golden Axe named §2§lPlot Wand
  - LEFT_CLICK_BLOCK = Set Position 1 (green message)
  - RIGHT_CLICK_BLOCK = Set Position 2 (green message)
  - Then /plot claim to purchase and protect the area.

FEATURE 7: PLOT MERGING
  - If a player owns two plots that are directly adjacent (touching),
    they can type /plot merge to combine them into one massive claim.
  - The wilderness blocks between them are automatically absorbed.

FEATURE 8: 7-DAY INACTIVITY NATURE RESET (FAWE)
  - When a player first claims a plot, the plugin silently saves a
    FAWE schematic (.schem) of the RAW, untouched terrain.
  - If the plot owner does not log into the server for X days
    (default: 7, configurable to 3, 10, 30, etc.), the plugin
    automatically PASTES the original schematic, perfectly restoring
    the land to pure nature as if no one ever built there.
  - The plot data is then deleted.
  - A Discord alert is sent to the admin channel.

FEATURE 9: PREMIUM PLOTS
  - Admins can define "Premium" plot tiers in the config.
  - Each tier requires a specific permission (e.g. plotmanager.premium.vip)
  - Premium plots cost more but have higher limits (more hoppers,
    spawners, vault pages, etc.)
  - The rank name is fully customizable in config.

# ------------------------------------------------------------------ #
# SECTION 2: PLOT PROTECTION (INSIDE PLOTS)                         #
# ------------------------------------------------------------------ #

FEATURE 10: ENTITY PROTECTION
  - Non-members cannot kill passive mobs (cows, sheep, pigs).
  - Non-members cannot shear sheep.
  - Non-members cannot trade with Villagers.
  - Non-members cannot leash or unleash animals.

FEATURE 11: BOUNCER SHIELDS (PARTICLE WALLS)
  - When you /plot ban <player>, that player is physically blocked.
  - If they try to walk into your plot, they hit an invisible wall
    made of green particles and get bounced backwards.
  - Uses PlayerMoveEvent to detect crossing the boundary.

FEATURE 12: STRICT TRUST LIMITS
  - /plot add <player> builder --no-chests
  - This means the player can break/place blocks but the plugin
    physically blocks them from opening ANY chest, barrel, shulker,
    or hopper in the plot.
  - Fully configurable trust flags per member.

FEATURE 13: COMPLETE BLOCK PROTECTION
  - BlockBreakEvent, BlockPlaceEvent — non-members blocked.
  - BlockPistonExtendEvent, BlockPistonRetractEvent — blocked from
    pushing blocks INTO or OUT OF a plot.
  - BlockFromToEvent — liquid (water/lava) cannot flow into a plot.
  - LeavesDecayEvent — leaves don't decay inside plots.
  - BlockSpreadEvent, BlockBurnEvent — fire cannot spread.
  - CreatureSpawnEvent — mob spawning toggleable per plot.

FEATURE 14: COMBAT TAGGING
  - If PvP is enabled in a plot and two players fight, the loser
    cannot safely log out. Combat tag lasts 5 seconds (configurable).
  - If they log out during combat, they drop their items.

# ------------------------------------------------------------------ #
# SECTION 3: ECONOMY & AUTOMATION                                   #
# ------------------------------------------------------------------ #

FEATURE 15: PLOT VAULTS (VIRTUAL STORAGE)
  - /plot vault — Opens a virtual double-chest.
  - This chest belongs to the PLOT, not the player.
  - Owner and Co-Owners can access it.
  - Upgradable: Tier 1 = 1 page (27 slots), Tier 2 = 2 pages, etc.
  - Each tier costs money to unlock (configurable in config).

FEATURE 16: PLOT GENERATORS
  - Generators are machines that automatically produce resources
    and deposit them into the Plot Vault.
  - Tier 1 Generator: 1 Iron Ingot every 10 minutes.
  - Tier 2 Generator: 1 Gold Ingot every 15 minutes.
  - Tier 3 Generator: 1 Diamond every 30 minutes.
  - Works even when the owner is OFFLINE.
  - All rates and costs are configurable.

FEATURE 17: TIP JARS
  - Owner places a sign with [Tip Jar] on the first line.
  - Any visitor can right-click the sign to donate money.
  - The donated money goes directly into the Plot Bank.
  - Minimum tip amount is configurable.

FEATURE 18: PLOT CHEST SHOPS
  - Owner places a sign on a chest with format:
      [Shop]
      <quantity>
      <item>
      <price>
  - Buyers right-click the sign to purchase items.
  - Money goes into the PLOT BANK (not personal wallet).
  - Supports Placeholder format for the sign lines.

FEATURE 19: GLOBAL MARKET GUI
  - /plot market — Opens a massive GUI showing ALL active chest
    shops across the entire server.
  - Players can search by item name.
  - Clicking a listing teleports you directly to that plot's shop.
  - Sorted by price (cheapest first).

FEATURE 20: PLOT LEVELING (EXP SYSTEM)
  - Plots start at Level 1 and can reach Level 100.
  - Plots gain EXP from:
      * Visitors spending time inside the plot
      * Tips donated via Tip Jars
      * Chest Shop sales
  - Higher levels unlock:
      * New particle border colors
      * Better generator tiers
      * More vault pages
      * The "Plot Lord" Discord role at Level 10

FEATURE 21: OFFLINE EARNINGS REPORT
  - When a plot owner logs into the server after being offline,
    the plugin gives them a Written Book item.
  - The book contains a detailed report:
      * Total visitors while offline
      * Total money earned from Chest Shops
      * Total tips received
      * Generator output summary
  - All formatted in green theme.

FEATURE 22: DISCORD LIVE CHAT SYNC (TWO-WAY)
  - Messages typed in Minecraft appear in a Discord channel.
  - Messages typed in the Discord channel appear in Minecraft.
  - Format is configurable: "[MC] %player%: %message%"
  - Channel ID is set in config.yml.

FEATURE 23: DISCORD ACTION LOGGER
  - Logs the following events to a separate Discord channel:
      * Player joins/leaves the server
      * Plot claimed (who, where, cost)
      * Plot deleted/unclaimed
      * 7-day nature reset triggered
      * Admin actions (freeze, seize, purge)
  - Channel ID is set in config.yml.

FEATURE 24: DISCORD ROLE SYNC
  - When a plot reaches Level 10 (configurable), the Discord bot
    automatically gives the plot owner a special role.
  - Default role name: "Plot Lord"
  - Role ID is set in config.yml.

FEATURE 25: BLUEMAP 3D WEB INTEGRATION
  - The plugin hooks into BlueMap API.
  - Draws 3D colored boxes (default: green #00FF00) around every
    claimed plot on the live web map.
  - Clicking a plot on the website shows a popup with:
      * Plot Name
      * Owner Name
      * Plot Level
      * Bank Balance
  - Border color and thickness are configurable.

FEATURE 26: THE MASTER GUI (/plot menu)
  - Opens a single central 54-slot inventory GUI.
  - From this ONE menu, players can click buttons to access:
      * Plot Info (shows stats in chat)
      * Bank (deposit/withdraw)
      * Members (add/kick/promote)
      * Flags (toggle PvP, mobs, fire, etc.)
      * Upgrades (buy Fly, Vaults, Generators)
      * Vault (open virtual storage)
      * Market (browse server shops)
      * Blackmarket (secret underground market)
      * Home (teleport to plot spawn)
      * Unclaim (shift-click to confirm)
  - Every GUI button ALSO has a command equivalent for players
    who prefer typing commands.

FEATURE 27: PLOT ROLES (4 TIERS)
  - Owner: Full control. Can delete, manage members, withdraw bank.
  - Co-Owner: Can add/remove members, toggle flags, access vault.
  - Builder: Can break/place blocks only.
  - Visitor: Can walk around and interact only.
  - /plot promote <player> and /plot demote <player> to change roles.

FEATURE 28: ADVANCED HOLOGRAMS (FANCYHOLOGRAMS STYLE)
  - Players can BUY holograms with money.
  - Max holograms per plot is configurable.
  - Commands:
      * /plot holo create — Creates a new hologram at your location
      * /plot holo addline <text> — Adds a line of text
      * /plot holo removeline <number> — Removes a specific line
      * /plot holo delete — Deletes the hologram
  - Built-in PROFANITY FILTER blocks bad words (configurable list).
  - Holograms display STATUS:
      * If plot is unclaimed: Shows status_free text (default: &a&lFREE)
      * If plot is claimed: Shows status_occupied text (default: &c&lOCCUPIED)
  - Status text is fully configurable in config.yml.

FEATURE 29: PLOT MUSIC
  - Players pay money to unlock a music disc for their plot.
  - When ANY player walks into the plot, the selected music disc
    starts playing automatically via note block sounds.
  - /plot music <disc_name> to select the track.
  - Music cost is configurable.

FEATURE 30: PLOT MAILBOXES
  - Owner types /plot setmailbox while looking at a Barrel.
  - Visitors can open the barrel and DROP items in.
  - Visitors are physically BLOCKED from taking items out.
  - Only the Owner/Co-Owner can retrieve items from the mailbox.
  - Perfect for receiving payments or deliveries.

FEATURE 31: LIVE PLOT MAP ITEM
  - /plot map — Gives the player a Map item.
  - When held, it displays a live radar view of the plot's borders.
  - Green dots show where members are currently standing.
  - Updates in real-time.

FEATURE 32: TITLE SCREENS & SOUND EFFECTS
  - When entering a plot: Big green title on screen showing the
    plot name and owner, plus a pleasant chime sound.
  - When leaving a plot: Subtitle saying "Wilderness" with a
    different sound effect.
  - Uses ActionBar and Title packets.

## 1. THE HOLOGRAM ENGINE (BUILT-IN)
The hologram system MUST be built from scratch using Bukkit's EntityType.ARMOR_STAND.
- Entities must be spawned with NBT tags: `Invisible:1b, Marker:1b, NoGravity:1b`.
- They must have a custom name and `CustomNameVisible:1b`.
- For multi-line holograms, spawn an ArmorStand for each line, separated by the `line_spacing` config value (default 0.28 blocks on the Y axis).
- Auto-Holograms update every `update_ticks`. Instead of destroying and respawning, the AI MUST keep a Map<UUID, List<ArmorStand>> and simply update `setCustomName(PlaceholderAPI.setPlaceholders(player, string))` for performance.

## 2. THE FAWE ROLLBACK SYSTEM (7-DAY RESET)
- When a plot is claimed, use FAWE's `CuboidRegion` to capture the area.
- Use `ClipboardFormat.SCHEMATIC.getWriter(new FileOutputStream(file))` to save the pristine nature.
- When `PlotManager.checkInactivity()` runs, if `System.currentTimeMillis() - plot.getLastLogin() > (inactivity_days * 86400000L)`, trigger the reset.
- Load the schematic using FAWE's `ClipboardFormat.SCHEMATIC.getReader(new FileInputStream(file))`.
- Paste it using `EditSession` with `flushQueue()` for zero lag.
- Delete the plot from `plots.yml` and remove the auto-hologram.
- Send webhook to Discord using JDA.

## 3. ABSOLUTE EXPLOSION & GRIEF PREVENTION
- `EntityExplodeEvent`: Check `e.blockList()`. Iterate through blocks. If `Block.getLocation()` is inside ANY plot, `e.blockList().remove(block)`. Do not cancel the whole event, just remove protected blocks.
- Do the same for `BlockExplodeEvent`.
- `EntityChangeBlockEvent`: Block Endermen from picking up blocks in plots.
- `PlayerInteractEvent`: Check `e.getAction() == Action.PHYSICAL`. Block crop trampling if `wilderness_crop_trample` is false, or if inside another player's plot.

## 4. THE BOUNCER SHIELD ALGORITHM
- In `PlayerMoveEvent`, check if `e.getFrom()` is outside the plot and `e.getTo()` is inside.
- If the player is in the plot's `banned_players` list, cancel the event.
- Compute the vector from the plot center to the player. Normalize it, multiply by `knockback_strength`.
- Apply `player.setVelocity(vector)`.
- Spawn a dense wall of `Particle.VILLAGER_HAPPY` (if set in config) at the plot border facing the player using `world.spawnParticle()`.

## 5. GENERATORS & OFFLINE EARNINGS
- Generators run on a `BukkitRunnable` every 1 minute.
- Instead of actually dropping items on the ground (which causes lag), the plugin adds the items directly into the `Plot Vault` (Virtual Inventory).
- If the Vault is full, the items are lost.
- When an owner logs in, calculate how many items were generated while offline by comparing `System.currentTimeMillis()` with `last_logout`. Add the items retroactively.

## 6. THE BLACKMARKET SYSTEM
- The Blackmarket GUI is an asynchronous virtual inventory.
- Items sold here bypass the 5% `chest_shops.tax_percent`.
- When a transaction occurs, roll a random number `ThreadLocalRandom.current().nextInt(100)`.
- If the number is < `blackmarket.snitch_chance_percent`, trigger the snitch event.
- Use `jda.getTextChannelById(log_channel).sendMessage()` to alert admins.

## 7. COMBAT TAGGING INSIDE PLOTS
- If the plot flag `PvP` is true, listen to `EntityDamageByEntityEvent`.
- If both entities are Players, put them in a `Map<UUID, Long>` tracking the combat timestamp.
- Listen to `PlayerQuitEvent`. If `Map.containsKey(uuid)` and `currentTime - timestamp < 5000` (5s combat tag), kill the player instantly using `player.setHealth(0)`.

## 8. VAULT VIRTUAL DOUBLE-CHESTS
- Store vault items as Base64 strings in the `plots.yml` file.
- Use Bukkit's serialization: `BukkitObjectOutputStream` to convert `Inventory` to a byte array, then Base64 encode it.
- When opening the vault, decode the Base64 string back into an `Inventory`.
- Tier 1 gets 27 slots (Chest). Tier 2+ gets 54 slots (Double Chest).

## 9. BLUEMAP INTEGRATION
- Connect to BlueMap API.
- For each plot, create an `ExtrudeMarker` using the plot's X, Z bounds and Y=min_height to Y=max_height.
- Set the `LineColor` to the hex value from the config.
- Update the marker's label whenever the plot's name or owner changes.
- Delete the marker when the plot is unclaimed or reset by FAWE.

## 10. ADVANCED EDGE CASES & EXPLOIT PREVENTION
- **Piston Push/Pull Exploits:** Players often try to push blocks into a plot using pistons from the wilderness. Listen to `BlockPistonExtendEvent` and `BlockPistonRetractEvent`. For every block in the `getBlocks()` list, check if its future location intersects with a plot boundary. If it does, and the piston owner is not a member, cancel it immediately.
- **Hopper Minecart Theft:** Players might place Hopper Minecarts under a plot's chests to steal items. Listen to `VehicleMoveEvent` and `InventoryMoveItemEvent`. If a hopper minecart crosses into a plot boundary, destroy it or cancel the item suction.
- **Dispenser Griefing:** Prevent dispensers in the wilderness from shooting TNT, arrows, or lava buckets into a plot. Check `BlockDispenseEvent`. If the dispenser is outside the plot but facing inside, cancel the event.
- **Liquid Flow Griefing:** Water and Lava must not flow into a plot from outside. In `BlockFromToEvent`, check `e.getBlock().getLocation()` (source) and `e.getToBlock().getLocation()` (destination). If source is in wilderness and destination is in plot, cancel.

## 11. ASYNCHRONOUS DATA SAVING (NO LAG)
- The AI MUST NEVER save `plots.yml` on the main server thread.
- Create an `AutoSaveTask` that runs every `auto_save_interval_minutes`.
- Use Bukkit's `Bukkit.getScheduler().runTaskAsynchronously()` to write data to disk.
- When the server shuts down (`onDisable`), use the main thread to forcefully save everything one last time to prevent rollback.

## 12. PACKET-BASED TITLES & ACTIONBARS
- Use the Paper API for titles: `player.showTitle(Title.title(Component.text(...)))` instead of old NMS packets. This is much cleaner and cross-version compatible.
- For the `Live Plot Map Item` (Feature 31), intercept `PacketPlayOutMap` using ProtocolLib (if available) to draw the green dots (members) and red dots (intruders) dynamically on the map canvas, bypassing normal Minecraft map rendering. If ProtocolLib isn't present, use Bukkit's `MapRenderer` API instead.

## 13. EXACT HOPPER & SPAWNER LIMITING ALGORITHM
- When a player places a hopper/spawner (`BlockPlaceEvent`), check the plot's `current_hoppers` count.
- If `current_hoppers >= plot_protections.hopper_limit`, cancel the event and send the `place_denied_message`.
- Crucial Edge Case: If a player breaks a hopper, decrement the count.
- Extreme Edge Case: If FAWE resets the plot, or TNT blows up a hopper (if explosions are allowed), the counter MUST be recalculated. Run an async scan of the plot chunks every 10 minutes to auto-correct the hopper/spawner counts.

## 14. IN-GAME PRICE EDITOR GUI LOGIC
- When an admin uses `/plot editprices` and clicks an item, close the GUI and put their UUID in a `price_edit_mode` Set.
- Listen to `AsyncChatEvent`. If the player is in the Set, cancel their chat message, parse it as a Double, update the config file in memory, and immediately save it using `yamlConfiguration.save(file)`.
- Play `ENTITY_EXPERIENCE_ORB_PICKUP` and remove them from the Set.
